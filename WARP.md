# WARP.md

This file provides guidance to WARP (warp.dev) when working with code in this repository.

## Project Overview
4DFlowNet is a deep learning implementation for super-resolution 4D Flow MRI using Residual Neural Networks. The active migration branch uses PyTorch + MONAI to upsample low-resolution velocity field data (from CFD simulations or MRI) to high-resolution predictions.

The network is based on the paper "4DFlowNet: Super-Resolution 4D Flow MRI" with v2.0 improvements including updated loss functions (MSE fluid + MSE non-fluid), L2 regularization, and linear final activation.

## Technology Stack
- PyTorch + MONAI
- Python 3.x
- NumPy, h5py for data handling
- pydicom for MRI DICOM data processing
- HDF5 format for all datasets

### Key Architectural Concepts

#### Network Architecture
The SR4DFlowNet processes 6 input channels (3 velocity components u,v,w and their magnitudes) through:
1. Initial conv3d layers that process phase and magnitude separately, then concatenate
2. Low-resolution residual blocks (default: 8 blocks) in original resolution
3. 3D upsampling layer (using bilinear interpolation)
4. High-resolution residual blocks (default: 4 blocks) in upsampled space
5. Three separate output paths for u, v, w velocity components with linear activation

Residual blocks use 3D convolutions with LeakyReLU activation and symmetric padding. The network supports arbitrary integer upsampling ratios via the `res_increase` parameter.

#### Data Pipeline
Training uses MONAI/PyTorch `DataLoader` via `PatchHandler3D`:
- Loads patch indices from CSV files (generated by `prepare_patches.py`)
- Each CSV row specifies: LR filename, HR filename, data index, x/y/z patch coordinates, rotation flags
- Supports data augmentation through 90/180/270 degree rotations
- Normalizes velocities by VENC (velocity encoding)
- Applies binary masking (threshold 0.6) to separate fluid/non-fluid regions
- Batch processing with prefetching for performance

#### Loss Function
The loss combines:
- MSE on fluid regions (mask >= 0.5)
- MSE on non-fluid regions (mask < 0.5)
- L2 regularization (weight: 5e-7) on convolutional kernels
- Divergence loss is available but disabled in v2.0 (`div_weight = 0`)

Accuracy metric is relative speed error calculated over masked regions.

## Common Commands

### Training
```bash
cd src
python trainer.py
```
Training configuration is set directly in `trainer.py`:
- Modify `data_dir`, `training_file`, `validate_file` for dataset paths
- Key hyperparameters: `initial_learning_rate`, `epochs`, `batch_size`, `patch_size`, `res_increase`
- Network parameters: `low_resblock` (8), `hi_resblock` (4)
- Set `restore = True` and specify `model_dir`/`model_file` to resume training
- Models save to `../models/[network_name]_[timestamp]/` with:
  - Best model: `[network_name]-best.pt`
  - Latest checkpoint: `[network_name]-latest.pt` (every 10 epochs)
  - Training log: `loss.csv`
  - TensorBoard logs: `tensorboard/train` and `tensorboard/validate`
  - Source code backup: `backup_source/`

### Prediction
```bash
cd src
python predictor.py
```
Configuration in `predictor.py`:
- Set `data_dir`, `filename` for input HDF5 file
- Set `output_dir`, `output_filename` for results
- Set `model_path` to pre-trained checkpoint (e.g., `../models/4DFlowNet/4DFlowNet-best.pt`)
- Parameters must match training: `patch_size`, `res_increase`, `low_resblock`, `hi_resblock`
- `round_small_values = True` zeros out velocities below 1 pixel value (venc/2048)

### Data Preparation Workflow

#### From CFD Data (Training)
1. Generate low-res from high-res:
```bash
cd src/prepare_data
python prepare_lowres_dataset.py
```
Edit the script to configure:
- `input_filepath`: High-res HDF5 file
- `output_filename`: Output low-res HDF5 file
- `downsample`: Downsampling ratio

2. Generate patch indices:
```bash
cd src/prepare_data
python prepare_patches.py
```
Configure:
- `lr_file`, `hr_file`: LR and HR HDF5 filenames
- `patch_size`: Must match network training patch size
- `n_patch`: Number of patches per time frame
- `all_rotation`: Enable/disable rotation augmentation
- Outputs CSV file with patch locations

#### From MRI DICOM (Prediction)
```bash
cd src/prepare_data
python prepare_mri_data.py --input-dir [DICOM_DIR] --output-filename [OUTPUT.h5]
```
Options:
- `--input-dir`: Directory with structure `[CASE]/[Phase_or_Magnitude]/[TriggerTime]`
- `--output-dir`: Output directory (default: `../../Dataset`)
- `--output-filename`: HDF5 output filename
- `--phase-pattern`, `--mag-pattern`: Series description patterns (default: `_P_`, `_M_`)
- `--fh-mul`, `--rl-mul`, `--in-mul`: Velocity direction multipliers

Requirements: Exactly 3 phase and 3 magnitude directories. Use [DicomSort](https://dicomsort.com/) to organize by SeriesDescription -> TriggerTime.

#### From MRI NIfTI (Training or Prediction)
```bash
cd src/prepare_data
python prepare_nifti_data.py \
  --u [U_NIFTI] --v [V_NIFTI] --w [W_NIFTI] \
  --mag [MAG_NIFTI] \
  --venc [VENC_M_PER_S] \
  --output-filename [OUTPUT.h5]
```
Notes:
- Supports 3D or 4D NIfTI; use `--time-axis` if time is not the last axis.
- Use `--mag-u/--mag-v/--mag-w` for per-component magnitudes.
- Provide `--mask` for training (or let it be generated from magnitude via `--mask-threshold`).
- Requires `nibabel`.

### Testing Data Pipeline
```bash
cd src
python test_iterator.py
```
Validates the MONAI/PyTorch data pipeline and patch loading without training.

## Data Format
All data uses HDF5 format with expected datasets:
- Training/Prediction input: `u`, `v`, `w` (velocity components), `mag_u`, `mag_v`, `mag_w` (magnitudes), `venc_u`, `venc_v`, `venc_w`, `mask`
- High-res ground truth: `u`, `v`, `w`, `mask`
- Prediction output: `u`, `v`, `w`, `dx` (optional spacing)

Shape: `[time_frames, x, y, z]` for 4D data or `[x, y, z]` for 3D

## Important Notes
- Work in `src/` directory when running scripts (paths are relative: `../data`, `../models`)
- The network expects isotropic patch sizes (e.g., 16x16x16, 24x24x24)
- Adjust `patch_size` and `batch_size` based on GPU memory
- `res_increase=1` performs denoising without upsampling
- Mask threshold (default 0.6) distinguishes fluid vs non-fluid regions
- Velocity normalization is by VENC; magnitude normalization is by 4095 (12-bit)
- Training creates timestamped model directories to avoid overwriting
